Your paid AI coding agent shouldn't go dead the moment you hit a rate limit.

QuotaSpill is a self-hosted proxy that keeps your real, paid Claude or OpenAI subscription as the primary route, and only spills over to a free-tier backup when the primary genuinely runs out of quota. Never before.

Why this exists

Every free-tier router on the market solves the same problem: stack a pile of free-tier accounts behind one endpoint and route across whichever one is healthiest right now. That's useful, but it inverts the priority for anyone who actually pays for Claude or OpenAI. If you already have a subscription, the model you want most of the time is the one you're paying for, not the cheapest one available.

QuotaSpill exists for the other half of that problem: stay online past your own quota, without giving up your paid model the rest of the time. Your real, paid provider is always tried first. A free-tier fallback only takes over when the primary actually returns a quota error, or when a budget cap you configured is reached. Nothing is silently masked: a bad request or bad API key is relayed to you exactly as the primary sent it.

What makes this different

Most self-hosted LLM routers are built around a catalog: they track dozens of providers and route to whichever free model scores best. QuotaSpill inverts that model entirely instead of extending it.

Typical free-tier routerQuotaSpill
What's primaryWhichever free model scores best right nowYour real paid subscription
Fails over whenAny provider hits its own capYour primary returns a quota error, or your budget cap is hit
Provider catalogDozens of providers tracked for youNone — you wire up 2–3 endpoints yourself
FootprintFull app: dashboard, database, container imageOne Node process, zero dependencies

Nothing stops you from pointing QuotaSpill's fallback at whatever free-tier backend you already run locally; it just doesn't assume one, ship one, or depend on one. That's what keeps it small enough to read end to end in one sitting.

How it works

1Request lands on /v1/messages (Anthropic wire) or /v1/chat/completions (OpenAI wire).
2If a monthly budget cap is already spent, skip straight to the fallback chain.
3Otherwise call the primary. A 429/529 quota-style error moves to the next provider; anything else (400, 401, 403…) is relayed to you immediately, unmodified.
4Streaming responses are piped through byte-for-byte; usage tokens are parsed off the SSE stream on the side, so the dashboard's savings estimate works for streamed answers too.
5Every response carries X-QuotaSpill-Source: primary:<name> or fallback:<name>, and a local dashboard tracks the split.

Quick start

git clone https://github.com/sunilgentyala/quotaspill.git
cd quotaspill
cp quotaspill.config.example.json quotaspill.config.json
cp .env.example .env
# edit .env: set ANTHROPIC_API_KEY / OPENAI_API_KEY, and FALLBACK_API_KEY

node --env-file=.env bin/quotaspill.js start
# dashboard: http://localhost:8787

Honest limitations

  • No cross-wire translation. A chain's primary and fallback must speak the same API shape; Anthropic-to-OpenAI translation isn't implemented.
  • Doesn't extend your real quota. The fallback answers with a different, usually weaker model. It keeps your agent's session alive, not your subscription's token count.
  • Budget caps count requests, not tokens, since that's the metering unit QuotaSpill controls directly.
  • Mid-stream drops aren't recoverable once the primary has already started streaming a 200 response.
  • Single-user, no auth of its own. Meant for localhost, like any self-hosted proxy of this kind.
